Overview

I mentioned in my about section that operating systems is the class that made me actually fall in love with programming, and this project is why. It started as the standard assignment sequence for Michigan's OS course, and I kept going past where the course stopped, because I wanted to see the whole picture connect: a thread library I wrote myself, a virtual memory pager sitting underneath it, and a networked filesystem built on top of both.

What got me was realizing how much of what I'd been treating as "how computers just work" — a thread waking up, a page fault resolving invisibly, a file read returning the right bytes — is actually a pile of deliberate engineering decisions that somebody had to get right. Building each layer myself instead of just reading about it was the only way I was going to really understand that.

Design & Implementation

The thread library taught me that the hard part isn't scheduling. I went in assuming the interesting problem would be picking a scheduling policy. It turned out the part that actually demanded care was context switching and synchronization — getting a thread's saved state exactly right so it resumes as if nothing happened, and making sure two threads touching shared state can't interleave in a way that corrupts it. Those are the bugs that don't show up every run, which taught me to be a lot more paranoid about concurrent code than any lecture did.

Virtual memory made "abstraction" feel real. Implementing the pager — managing page tables, handling page faults — is where the idea of virtual memory stopped being a diagram in a textbook and became something I had to get exactly right or watch the whole system behave incorrectly in confusing ways. There's a particular kind of understanding that only comes from debugging a page fault handler that isn't doing what you expect.

Why I layered the filesystem on top instead of building it standalone. By the time I got to the networked filesystem piece, I already had a thread library and a memory system to build on — which meant I got to feel, directly, how much a higher layer depends on the correctness of the layers underneath it. A subtle bug in the pager doesn't stay contained to the pager; it shows up as a weird, hard-to-explain failure two layers up. That's the lesson from this project I've carried into everything since: get the foundation right, because you will absolutely pay for it later if you don't.
